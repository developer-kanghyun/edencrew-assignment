# assets/mock — 네이버 API 실제 응답 샘플

파싱 테스트의 입력으로 쓰는 파일입니다. 실제 endpoint를 호출해 받은 응답을
**서버가 준 바이트 그대로** 저장했습니다. UTF-8로 변환하지 않았습니다.

| 파일 | endpoint | 인코딩 | 요청 |
|---|---|---|---|
| `search_autocomplete.json` | 검색 자동완성 | UTF-8 | `q=삼성` |
| `realtime_quote.json` | 실시간 시세 | **EUC-KR** | `005930,000660` |
| `stock_meta.json` | 종목 메타데이터 | UTF-8 | `005930` |
| `daily_price_page1.html` | 일별 시세 | **EUC-KR** | `005930` 1페이지 |
| `daily_price_page2.html` | 일별 시세 | **EUC-KR** | `005930` 2페이지 |

수집 시점: 2026-09-11

## 왜 원본 인코딩 그대로 저장했나

UTF-8로 변환해 저장하면 편하지만, 그러면 EUC-KR 디코딩 로직을 테스트가 검증하지
못합니다. 원본 바이트를 두어야 "바이트 수신 → 디코딩 → 파싱" 전 과정을 확인할 수
있습니다. 검증은 `test/euc_kr_decoding_test.dart`에 있습니다.

## 일별 시세가 2페이지인 이유

한 페이지에 10거래일이 들어 있습니다. 기간 탭이 요구하는 거래일 수만큼 페이지를
이어 받고 이미 받은 페이지는 재사용하는데, 그 동작을 검증하려면 페이지가 둘 이상
필요합니다.
